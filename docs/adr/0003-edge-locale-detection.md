# ADR 0003: Определение локали на edge (CloudFront Function)

Статус: принято

## Context
Статический хостинг S3 + CloudFront не умеет серверное согласование языка, а `/` не содержит контента и должен вести на локаль (ТЗ v3 §2): cookie `lang` → `Accept-Language` с q-значениями → `en`; query string сохраняется; прямые `/en/...` и `/ru/...` не редиректятся; боты обрабатываются так же (без клоакинга); редирект не должен попасть в кэш не тому пользователю. Новой runtime-инфраструктуры, кроме CloudFront Function, нельзя добавлять. Заодно OAC + S3 не отдают `index.html` для подкаталогов, а при `trailingSlash: true` пути вида `/ru/` требуют переписывания.

## Decision
- CloudFront Function `locale-router` (runtime `cloudfront-js-2.0`, исходник в `infra/functions/`), привязана к **viewer-request** default behavior; управляется Terraform вместе с distribution.
- Для URI ровно `/`: ответ 302 на `/{locale}/` + исходный query string (параметры переносятся как есть) и заголовок `Cache-Control: no-store`. Выбор локали: (1) cookie `lang` ∈ {`en`,`ru`}; (2) `Accept-Language`, ранжирование по q (q=0 исключает язык, при равенстве — порядок в заголовке), берётся первый поддерживаемый основной субтег (`ru-RU` → `ru`); если первым по рангу поддерживаемым является `ru` — `/ru/`; (3) иначе `/en/`.
- Для прочих URI: **никаких редиректов**; только переписывание `/x/` → `/x/index.html` (URI с завершающим `/`); пути с расширением остаются без изменений. Поэтому `/en/` и `/ru/` всегда отдают 200 и не зависят от cookie и заголовков.
- Кэш: вместо расширения cache key по cookie/`Accept-Language` используется `Cache-Control: no-store` на редиректе; ответы Function, сгенерированные на viewer-request, не кэшируются CloudFront. Статические страницы кэшируются как в v1.
- Функция не логирует и не сохраняет персональные данные (без `console.log` заголовков/cookie).
- Cookie `lang` выставляет клиентский переключатель (`Path=/; Max-Age=31536000; SameSite=Lax; Secure`), а не Function.
- Отвергнуто: Lambda@Edge (дороже, холодные старты, регион us-east-1, лишняя runtime-инфраструктура); клиентский JS-редирект на `/` (мигание, плохо для SEO/ботов); cache policy с ключом по cookie и `Accept-Language` (снижает hit ratio, сложнее).

## Consequences
+ Минимальная стоимость и задержка, нет новых runtime-сервисов; редирект работает без JS и одинаково для ботов.
+ Единая Function решает и локаль, и index-переписывание.
− Ограничения cloudfront-js-2.0 (ES 5.1-подобный набор, лимиты по размеру и времени): парсер `Accept-Language` должен быть простым; покрывается юнит-тестами (Node) и E2E (сценарии 1–3, 6).
− `no-store` значит, что каждый заход на `/` вызывает Function (копеечная стоимость).
− Список поддерживаемых локалей дублируется в Function; при добавлении локали его нужно обновлять (см. architecture.md, раздел 7).

# ADR 0002: Статические локали, файлы сообщений и локализованная 404

Статус: принято

## Context
ТЗ v3: локали `en` (default/fallback) и `ru`; `/en/` и `/ru/` полностью пререндерятся при сборке; нет runtime-сервера. Строки не хардкодятся; сборка падает при расхождении ключей; неизвестные пути ведут на 404 своей локали (фолбэк `en`). Архитектура должна позволять добавить локаль файлом сообщений и маршрутом. Middleware и i18n-routing Next.js несовместимы с `output: 'export'`.

## Decision
1. **Маршрутизация:** сегмент `app/[locale]/` с `generateStaticParams()` по списку локалей из одного модуля `apps/web/src/i18n/config.ts` (`['en','ru']`, default `en`). Результат: `out/en/index.html`, `out/ru/index.html`. `<html lang>`, metadata, hreflang, canonical и `og:locale` формируются из локали.
2. **Сообщения:** `apps/web/messages/{locale}.json`, плоские/вложенные ключи; компоненты получают строки только через i18n-хелпер. Название «KRunAI» не переводится.
3. **CI-проверка ключей:** скрипт в `apps/web` (запускается в `lint` и перед `build`) сравнивает множества ключей всех локалей с `en` и завершается с ненулевым кодом при любом расхождении. Те же сообщения используются формой (в т.ч. коды ошибок бэкенда → локализованный текст).
4. **404 по локали:** для каждой локали пререндерится страница `/{locale}/404/` → `out/{locale}/404/index.html`. CloudFront custom error response для 403 и 404 отдаёт **единый** `/en/404/index.html` со статусом 404 (CloudFront не умеет выбирать страницу ошибки по пути запроса). Страница 404 — клиентский компонент, определяющий локаль по `location.pathname`: префикс `/ru/` → RU-текст, иначе EN (фолбэк). Серверная `/{locale}/404/` остаётся доступной для прямого использования и ссылок.
   - Альтернатива, отвергнутая: отдельные CloudFront-поведения/Function на каждую локаль для ошибок — усложняет конфигурацию, а ошибки origin (403/404) всё равно обрабатываются на уровне distribution.
   - Альтернатива, отвергнутая: Lambda@Edge/Function в origin-response — нарушает запрет на новую runtime-инфраструктуру.
5. **Добавление локали:** файл сообщений + запись в `config.ts` (процедура — в `docs/architecture.md`, раздел 7).

## Consequences
+ Все страницы статические, кэшируются как в v1, не нужен runtime.
+ Расхождение переводов ловится в CI, а не в продакшене.
− 404 для `/ru/...` формально отдаётся из `/en/404/index.html`; RU-текст появляется после гидрации JS (кратковременно возможен EN-текст; для краулеров 404-статус корректен, `noindex` на странице). Для пользователей без JS — английский фолбэк (допустимо по ТЗ).
− Список локалей дублируется в трёх местах при авто-определении (`config.ts`, Function, allow-list API); это зафиксировано в процедуре и проверяется E2E.

# krunai.uz: выкатка по правилам платформы (изменения относительно v1–v3)

## Контекст
В v1–v3 предполагалась схема S3 + CloudFront + Lambda, доступ через роль, которую создаёт оператор, ручной сигнал клиента «готово» по DNS и автодеплой после мержа. Эта версия заменяет всё перечисленное на стандартный процесс платформы и golden path. Функциональные требования к контенту, i18n (EN/RU) и форме заявки из v1–v3 не меняются.

## 1. Стек и инфраструктура (golden path)
- Frontend: Next.js + TypeScript + Tailwind. Лендинг EN/RU (локали /en и /ru, определение по Accept-Language, выбор пользователя хранится в cookie), как в v2.
- Backend: Python + FastAPI, endpoint `POST /api/lead` для формы заявки (валидация, honeypot + rate limit, отправка через Amazon SES).
- Хостинг: AWS ECS Fargate, регион eu-west-3 (Paris). Два сервиса (web, api) за одним Application Load Balancer: маршрутизация `/api/*` → api, остальное → web.
- TLS: сертификат ACM в eu-west-3 на krunai.uz и www.krunai.uz с DNS-валидацией. Listener 80 перенаправляет на 443. Правило ALB: www.krunai.uz отдаёт 301 на https://krunai.uz.
- PostgreSQL не используется: приложение не хранит данные, заявки только отправляются письмом. Это осознанное отступление от golden path, потому что хранить нечего. Хранение заявок указано в открытых вопросах.
- Email: SES в eu-west-3, домен krunai.uz верифицируется через Easy DKIM (3 CNAME), custom MAIL FROM на mail.krunai.uz (MX + TXT SPF на поддомене). From: noreply@krunai.uz, To: gulmira@krunai.uz, Reply-To: email посетителя, в письме указан язык формы. Если аккаунт SES находится в sandbox, в отчёт о выкатке добавляется запрос на выход из sandbox, либо верифицируется получатель gulmira@krunai.uz.
- Существующие записи Zoho (MX, SPF, DKIM zmail, DMARC на apex) не изменяются и не дублируются.
- Логи: CloudWatch Logs для обоих сервисов, хранение 30 дней. В логах не должно быть содержимого сообщений и персональных данных сверх необходимого: email маскируется.
- Секреты и конфигурация задаются через переменные окружения и параметры задачи ECS. Долгоживущие ключи AWS в репозитории и CI запрещены.

## 2. Процесс выкатки по правилам платформы
- Инфраструктура описана как код в репозитории emustapaev/test1 в формате, который поддерживает пайплайн выкатки платформы. Ручные изменения в консоли AWS не допускаются.
- Доступ к AWS клиента предоставляется только через кнопку «Подключить AWS» (/aws): клиент подтверждает подготовленный стек в своей консоли. Шаги про роль, которую создаёт оператор, удаляются из документации и задач.
- CI (GitHub Actions) только собирает проект, запускает линтеры и тесты и собирает Docker-образы. Автоматического деплоя в AWS по push или merge нет. Workflow с автодеплоем из v1–v3 удаляется.
- Деплой в AWS выполняется только после подтверждения клиента кнопкой «Выкатить» (/deploy).
- После первой выкатки платформа формирует таблицу DNS-записей для ClouDNS из outputs стека. Выкатка не блокируется на ожидании DNS.

## 3. DNS-записи (передаются клиенту ботом после первой выкатки)
| Назначение | Тип | Имя | Значение |
|---|---|---|---|
| Валидация ACM | CNAME | 1–2 записи из ACM | из ACM |
| Сайт | ALIAS (ClouDNS) | krunai.uz | DNS-имя ALB |
| Сайт | CNAME | www | DNS-имя ALB |
| SES DKIM | CNAME ×3 | `<token>._domainkey` | `<token>.dkim.amazonses.com` |
| SES MAIL FROM | MX | mail | feedback-smtp.eu-west-3.amazonses.com (priority 10) |
| SES MAIL FROM | TXT | mail | `v=spf1 include:amazonses.com ~all` |

- Запасной вариант без ALIAS: основным адресом становится www.krunai.uz, а apex перенаправляется через веб-редирект ClouDNS (как в v3).
- Список значений должен быть доступен как outputs стека в машиночитаемом виде.

## 4. Критерии приёмки
1. В репозитории нет workflow, который деплоит в AWS при push или merge. CI запускает только сборку, линтеры и тесты и проходит успешно.
2. Инфраструктура полностью описана в коде и разворачивается с нуля в eu-west-3 через пайплайн платформы без ручных шагов в консоли.
3. Outputs стека содержат все записи из раздела 3 с точными значениями: ACM-валидация, DNS-имя ALB, 3 DKIM, MX и TXT для mail.krunai.uz.
4. До добавления DNS-записей лендинг открывается по DNS-имени ALB по HTTP, а `POST /api/lead` возвращает корректный ответ валидации.
5. После добавления записей https://krunai.uz отдаёт 200 с валидным сертификатом, http:// и https://www.krunai.uz отдают 301 на https://krunai.uz.
6. Тестовая заявка из EN и RU версий приходит на gulmira@krunai.uz от noreply@krunai.uz. В письме указан язык, Reply-To равен email посетителя, DKIM и SPF проходят (dkim=pass, spf=pass по mail.krunai.uz).
7. Записи Zoho (MX, SPF, DMARC) остаются без изменений, почта на gulmira@krunai.uz продолжает приходить.
8. В репозитории и CI нет AWS access keys и секретов.
9. Документация (README и docs/deploy) описывает процесс /aws → «Выкатить» (/deploy) → таблица DNS от бота → автопроверка. Упоминаний о том, что оператор присылает инструкции, и ручного сигнала «готово» в ней нет.
10. Health-check endpoints: web `/` и api `/api/health` отдают 200, ALB target groups в состоянии healthy.

## 5. Нефункциональные требования
- Безопасность: security groups открывают задачам ECS доступ только от ALB, ALB принимает трафик только на 80/443. В IAM task roles минимальные права: api может только ses:SendEmail от identity krunai.uz. Security headers (HSTS, X-Content-Type-Options, Referrer-Policy, CSP).
- Производительность: Lighthouse Performance ≥ 90 на мобильных для обеих локалей. Размер сервисов минимальный: 1 задача на сервис, 0.25 vCPU / 0.5 GB, автоскейлинг до 2.
- Защита формы: honeypot, rate limit 5 заявок в минуту с одного IP, ограничения длины полей.

## 6. Устаревшие задачи
Задачи из v1–v3 про S3/CloudFront/Lambda, роль от оператора, автодеплой в CI и ручной сигнал «готово» по DNS закрываются или переписываются под эту версию.

## 7. Открытые вопросы
- Нужно ли сохранять заявки, например в PostgreSQL или в другом хранилище, на случай сбоя почты? Сейчас не сохраняются.
- Находится ли SES в аккаунте клиента в sandbox? Это проверяется при первой выкатке.
- Поддерживает ли тариф ClouDNS клиента записи ALIAS? Если нет, используется запасной вариант.
